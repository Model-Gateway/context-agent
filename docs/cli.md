# CLI reference

Global flags: `--config <file>`, `--repo <dir>`, `--model <name>`, `--profile approval_required|workspace_autonomous|bypass_permissions`, `--effort low|medium|high|ultra`, `--data-dir <dir>`, `-v/-vv/-vvv`.

- `ctx` — interactive session (full screen). Enter runs a task; ↑/↓ open a menu of earlier prompts in this repository (Enter runs one, typing edits it, Esc restores what you were typing); `/` opens command suggestions (Tab completes); `@` opens the installed apps and the repository's files (Tab or Enter inserts `@name ` or `@path `; a mentioned app's tools are preferred for that message, a mentioned file's current text goes with it); the mouse wheel, PgUp/PgDn and Home/End scroll the conversation; Ctrl-C cancels (twice quits); Esc quits when idle; Ctrl-O shows thinking text and every sub-agent's tool calls and full report; Ctrl-T shows the event log; Shift-Tab cycles approval modes (ask → auto; bypass only by name); `/effort auto|low|medium|high|ultra` sets the reasoning effort (ultra lets the model deploy sub-agents, shown as a "◈ N agents" block with one row per agent); `/signin` signs in to ModelGateway with a device code (the browser opens on the approval page; the key goes to `<data_dir>/credentials.toml`) and points `model.base_url` in the user configuration file at the gateway, with `model.credential = "modelgateway"` and the project header; `/signout` revokes the key and puts the previous `model.base_url` back; `/usage [today|24h|7d|30d|90d|year|all|<n>h|<n>d] [model:<name>[,<name>…]] [project:<name>[,<name>…]]` shows the signed-in account's balance, plans and spend for the period (default 30 days; `all` is everything the gateway keeps, up to 400 days): a cost sparkline (per hour for periods of up to two days, per day otherwise), then the top models and projects; `model:` and `project:` keep only rows whose name contains one of the given parts, case-insensitively (`project:unattributed` matches requests sent without a project), and Tab completes periods and filter keys; `/billing` lists the billing preference, credit top-up options and plans on sale, `/billing topup <amount>` and `/billing plan <id>` open a checkout page in the browser, `/billing plan <id> balance` prices a plan paid from the balance and `/billing confirm` buys it, and `/billing prefer plan-first|balance-first|plan-only|balance-only` sets what requests draw on first; `y`/`n`/`a` answer approval prompts, also for sub-agents. The session reports mouse clicks and the wheel to `ctx`, so select text with the terminal's bypass modifier (Option-drag in iTerm2 and Terminal.app, Shift-drag in most others). The status line shows the model, approval mode, reasoning effort (when set), context, tokens, cost and index generation.
- `ctx init [--repo] [--force]` — write configuration templates.
- `ctx run "<task>" [--json] [--approval ask|auto|deny] [--timeout S] [--max-steps N] [--no-stream] [--no-probe] [--session ID | --new-session] [--variant A..E]` — headless run; JSON mode prints events on stderr and the outcome on stdout.
- `ctx index status|rebuild|watch`
- `ctx context explain|sources|stats [--query "..."] [--task ID]`, `ctx context show [--task ID]`
- `ctx memory list [--category c] [--all] [--limit n]`, `ctx memory search "..."`, `ctx memory forget <id>`
- `ctx task list [--limit n]`, `ctx task show <id>`
- `ctx diff [path]`
- `ctx eval run [tasks] [--variants A,B] [--filter id,id] [--mock] [--output file] [--keep]`, `ctx eval retrieval [queries.jsonl] [--output file]`
- `ctx doctor [--probe]` — also connects the configured MCP servers and reports each one's state.
- `ctx mcp list` — connect every configured MCP server and print its state and tool count; `ctx mcp tools [server]` — the tools (qualified names, read-only / destructive marks, descriptions); `ctx mcp add <name> [--env KEY=VALUE]… [--cwd DIR] [--tool NAME]… [--disabled] -- <command> [args…]` or `ctx mcp add <name> --url <url> [--header 'Name: value']…` — write a `[mcp.servers.<name>]` table into the user configuration; `ctx mcp remove|enable|disable <name>`; `ctx mcp catalog` lists the app catalog, `ctx mcp install <id> [--env KEY=VALUE]…` installs an app from it and `ctx mcp uninstall <id>` removes it (a default app such as `computer-use` stays removed, and a stored sign-in is forgotten); `ctx mcp login <id>` signs in through the browser (GitHub device flow) and installs the app with that sign-in, `ctx mcp logout <id>` forgets the sign-in. In the interactive session `/mcp` shows the same state. `ctx mcp-serve <name>` (hidden) runs a built-in server over stdio for the `builtin` transport.
